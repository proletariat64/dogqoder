# Qworker AC6 and AC11 Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or execute inline task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close AC6 with trustworthy host-enforcement plus live-containment evidence, and close AC11 by making an accepted normal stop outrank a later interrupt-generated result.

**Architecture:** Keep auditor safety enforcement in the host-owned SDK permission callback and treat live model tool attempts as optional telemetry, not proof. Keep result persistence unchanged, but derive the attempt terminal state from event ordering: a result phase accepted before stop remains completed/failed; a stop registered before a result phase makes the attempt cancelled while retaining the result summary.

**Tech Stack:** Python 3.12, asyncio, pytest/pytest-asyncio, qoder-agent-sdk 1.0.13, bundled QoderCLI 1.1.23, SQLite-backed `WorkerStore`.

**Spec:** `docs/superpowers/specs/2026-08-24-qoder-worker-design.md`

## Global Constraints

- Keep `qoder-agent-sdk==1.0.13` and bundled QoderCLI runtime `1.1.23`; do not switch to external QoderCLI 1.1.28.
- Preserve exact worker ID, attempt, cwd, result summary, and workspace contents across normal stop.
- Treat `completed`, `failed`, and `cancelled` as terminal for one attempt.
- Auditor enforcement must deny filesystem mutation, shell execution, unknown tools, nested mutation, and nested-agent recursion at the host permission boundary.
- Never retain prompts, tool inputs, credentials, agent identifiers, or model response text as acceptance evidence.
- Run real-Qoder tests only after all credential-free gates pass.

- [x] **Step 3: Record whether ResultEvent or stop was accepted first**

Add an optional synchronous `on_result` observer to both foreground runners. Invoke it exactly once when the adapter receives its first `ResultEvent`. In `Supervisor._run_worker`, capture whether that event arrived before the attempt-scoped stop marker, then pass the fact into result persistence:

```python
result_preceded_stop = False

def on_result() -> None:
    nonlocal result_preceded_stop
    result_preceded_stop = (worker_id, attempt) not in self._stop_requests
```

In `Supervisor._persist_accepted_result`, choose `cancelled` only when stop is registered and `result_preceded_stop` is false. Continue recording the `WorkerResult` before emitting `worker.health_changed` and `worker.state_changed`, then discard the stop marker. This explicit observation is required because a result can already be inside adapter settlement before `_result_phases` exists.
