# Domain docs

This repository uses a single-context domain documentation layout.

## Before exploring

Read these when they exist:

- `CONTEXT.md` at the repository root
- Relevant ADRs under `docs/adr/`

Proceed silently when they do not exist. Domain-modeling workflows create them when terminology or architectural decisions need recording.

## Vocabulary

Use terms defined in `CONTEXT.md` in issue titles, plans, tests, and implementation. Avoid synonyms the glossary rejects.

If a needed concept is absent, reconsider whether it belongs to the project or record the gap for domain modeling.

## ADR conflicts

Surface any conflict with an existing ADR explicitly instead of silently overriding it.
